# L0CK3D-Recovery — C3RB3R 勒索软件数据抢救工具

> ## ⚠️ 请先读我：恢复是概率性的，不是 100%
>
> **本工具不能保证恢复任何文件。** 能救回多少，完全取决于每个文件的大小、类型和
> 它被加密时命中的档位——这是该勒索软件的加密策略决定的，不是工具性能问题：
>
> - **小于 1MB 的文件（绝大多数文档、小图）被整体加密，恢复率为 0**，本工具无法帮忙，
>   只能依靠：NAS 快照 / Hyper Backup / 向发送方重新获取；
> - **大于 5MB 的音频/视频**：约 12% 的数据被加密，实测可救回 **约 88%** 的内容
>   （音频可直接播放；视频帧可提取，装配播放还需一份编码参数）；
> - **照片**：仅部分相机（如三星）内嵌的预览图可救（640×480），主图无法恢复；
> - 所有比例均来自真实样本实测，你的文件结果可能不同。
>
> 使用前请先阅读下方"各类型恢复效果"表格，建立合理预期。
> 原始加密文件不会被本工具修改，请务必保留。


针对 **C3RB3R 勒索软件**（扩展名 `.L0CK3D` / `.LOCK3D`，基于 2022 年泄露的
Conti v3 源码，曾通过 CVE-2023-22518 等漏洞大规模攻击群晖等 NAS 设备）加密的文件，
在**不支付赎金、不接触攻击者**的前提下，从幸存数据中尽可能抢救回可播放/可查看的内容。

单文件、零依赖（纯 Python 标准库，Python 3.8+；安装 Pillow 可增强 JPG 校验）。
**不会修改你的原始加密文件。**

## 快速开始

```bash
# 批量处理整个文件夹（自动扫描、分类、抢救、生成报告）
python l0ck3d_recovery.py /path/to/加密文件夹

# 处理单个文件
python l0ck3d_recovery.py "xxx.mp4.L0CK3D" -o ./输出目录
```

运行后产物：
- `*_recovered/` 目录：抢救出的音频/图片/帧数据
- `报告.md`：每个文件的分诊结论与处理详情

## 原理：这个勒索软件的加密策略（逆向自真实样本 + Conti v3 泄露源码）

加密文件容器 = `[数据区][304B 密钥材料][264B 零][20B 尾注]`

按原始文件大小分三档（尾注模式字节可精确识别）：

| 原始大小 | 模式 | 加密范围 | 幸存明文 | 可抢救性 |
|---|---|---|---|---|
| ≤ 1MB | FULL (0x24) | 100% | 0 | ❌ 无法解密，只能靠快照/备份/重新获取 |
| 1~5MB | HEADER (0x26) | 仅前 1MB | ~80% | 🟡 视类型：JPG 可雕嵌入预览、PDF 部分可救 |
| > 5MB | PARTLY (0x25) | 3 段均匀分布，约 12% | **~88%** | ✅ 大部分数据可重建 |

分段算法（PARTLY）：`PartSize=(原始大小//100)*4`，3 段加密均匀分布，第 3 段必达文件尾。

## 各类型恢复效果（实测）

| 类型 | >5MB | 1~5MB | ≤1MB | 说明 |
|---|---|---|---|---|
| **FLAC** | ✅ ~88% 可播放 | ✅ 类似 | ❌ | 从明文区提取帧切片，重建文件头（CRC 全验证） |
| **MP3** | ✅ ~88% | ✅ 切头即可播 | ❌ | 帧自包含，定位帧同步后直接输出 |
| **WAV** | ✅ | ✅（实验性） | ❌ | 重写 RIFF 头，采样率需人工试听 |
| **JPG** | ⚠️ 预览图在尾部加密区 | ✅ 嵌入预览图可雕 | ❌ | 三星等相机普遍内嵌 640×480 预览 |
| **MP4/MOV** | 🟡 88% 帧可提取 | 🟡 | ❌ | HEVC/H264 裸流装配需参数集（见下） |
| **PNG / PDF / 文档** | ⚠️ 部分 | ❌ | ❌ | 参数集在加密区即无法解码 |

**视频为什么不能直接播？** HEVC/H264 的每帧数据按"编码器当时的配置"压缩，
配置（SPS/PPS 参数集，几十个字段）写在文件头部/尾部——两个位置都在加密区。
没有精确参数集，任何解码器都无法还原图像。解决办法二选一：
1. 原视频如果来自网络（如小红书/B站），**重新下载就是无损原版**；
2. 找一个**同账号/同设备/同工具导出的其他视频**（4K 对 4K），提取它的
   参数集（VPS/SPS/PPS，通常在文件头几百字节）注入帧数据即可播放。
   这也是专业视频取证工具（untrunc 等）的标准做法。

**音频为什么能直接播？** MP3 帧完全自包含；FLAC 的文件头可以从帧数据反推重建；
WAV 只需 44 字节文件头。音频参数空间小，纯靠文件本身即可恢复。

## 受害者必读（重要程度不亚于恢复数据）

1. **先断网、改密码**——堵住入侵入口（此类攻击常通过暴露的 DSM 端口/弱密码/Confluence 漏洞进入）；
2. **检查 DSM 快照和 Hyper Backup**——哪怕一个攻击前的快照，所有文件（包括 <1MB 的）全部复活；
3. **不要支付赎金**——该家族基于泄露源码，密钥为密码学安全随机数（RSA-2048 封装），
   支付无保障且资助犯罪；可提交样本到 [No More Ransom](https://www.nomoreransom.org) 和 ID Ransomware；
4. 本工具**不会修改原始加密文件**，请保留它们——未来若攻击者私钥泄露（有先例），全部文件可解。
